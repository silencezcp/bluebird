1. 软件简介

Nacre FTP 是一个 FTP / FTPS / SFTP 三合一的双栏文件传输客户端。界面结构参考

FileZilla Client（左右双栏 + 传输队列 + 日志），视觉风格改为现代奶白色，

并且所有颜色都可以由你自定义。

支持哪些协议

协议说明默认端口
FTP标准文件传输协议，不加密21
FTPSFTP over explicit TLS，控制通道与数据通道都加密21
SFTPSSH File Transfer Protocol，走 SSH 通道，全程加密22

主要特性

  • 双栏布局，本机与服务器对照操作
  • 拖拽传输（面板之间拖，也可以从 Windows 资源管理器拖进来上传）
  • 传输队列：并发、暂停/继续、取消、失败自动重试、实时速率与进度条
  • 传输完成弹窗（成功/失败/批量汇总）并自动刷新对应面板
  • 中英文双语界面，可随时切换、无需重启
  • 主页按钮直达桌面；本地面板可切换盘符（含网络盘、可移动盘）
  • 文件大小自动换算单位（B / KB / MB / GB / TB）
  • 服务器不返回文件大小时自动后台补齐
  • 远程文件编辑、权限修改、递归删除、文件夹大小统计
  • 连接信息自动保存到本地 config.ini，可手工编辑与迁移
  • 34 项界面颜色全部可改，带冲突检测，内置 4 套主题预设
  • 内置用户手册（Help 菜单，程序内查看 / 导出 PDF）
  • 纯 Python 实现，无编译步骤，无注册表写入；可打包为单文件 exe

2.2 安装依赖

如果还没装依赖：

D:\DSH_Workspaces\Ftp\python.exe -m pip install -r requirements.txt ^
    --index-url https://mirrors.aliyun.com/pypi/simple/

2.3 启动

方式一：双击 NacreFTP.exe（打包版，无需安装 Python）

方式二：双击 run.cmd（源码版，自动使用配套的 Python 3.8）

方式三：命令行

D:\DSH_Workspaces\Ftp\python.exe run.py

方式四：带连接参数启动，会预先填好连接对话框

run.cmd sftp://deploy@sftp.example.com:22
run.cmd ftp://user@192.168.1.10
run.cmd sftp://user@host:22/var/www        :: 直接进入指定目录

首次启动会创建配置目录 %APPDATA%\.nacreftp\，并在其中生成

settings.json（偏好设置）与 config.ini（保存的连接）。

4. 连接服务器

4.1 用连接栏快速连接

  1. 在连接名框输入一个名字（例如 Production web server）；

留空也可以，程序会自动用 用户名@主机 作为名字。

  1. 选择协议（FTP / FTPS / SFTP）。
  2. 填主机、端口（切换协议时会自动填默认端口）、用户、密码。
  3. 点 Connect，或直接按回车。

连接成功后：

  • 状态栏显示 Connected to "连接名" — ftp://user@host:port
  • 窗口标题变成 Nacre FTP [连接名]
  • 日志记录 Connection saved to config.ini as "连接名"
  • 远程面板自动进入该连接上次使用的目录

4.2 用连接对话框连接

点 Connect（连接栏为空时）或 File ▸ Connect…（Ctrl+N）打开对话框：

字段说明
Connection name必填。连接名，留空无法确定。右侧 ↺ 恢复建议名
ProtocolFTP / FTPS / SFTP
Host主机名或 IP
Port端口，切换协议自动更新
User用户名；勾选匿名登录后自动填 anonymous
Password密码，右侧眼睛图标可查看明文
Private key仅 SFTP：可选的 OpenSSH 私钥文件（id_rsa / id_ed25519 等）
Log in anonymously匿名登录
Save this connection to config.ini默认勾选；取消勾选则本次连接不写入文件

对话框底部会显示配置文件的完整路径。

4.3 用已保存的连接连接

菜单 File ▸ Recent connections 分两组：

  • Saved connections (config.ini) —— 所有已保存的连接，点一下直连（含密码）
  • Recently used —— 最近用过的连接名

也可以用 File ▸ Site manager…（Ctrl+Shift+S）打开站点管理：

  • 列表显示所有已保存连接，鼠标悬停看协议/主机/端口/用户/是否保存了密码
  • Connect —— 连接选中的连接
  • Rename… —— 重命名（同时更新 config.ini 里的区段与索引）
  • Delete —— 从 config.ini 删除
  • 双击列表项直接连接

4.4 SFTP 使用私钥登录

  1. 协议选 SFTP
  2. Private key 选你的私钥文件（例如 C:\Users\你\.ssh\id_ed25519）
  3. 密码可以留空（密码仅用于解密私钥口令）
  4. 如果私钥有口令，填在 Password 框里

服务器主机密钥的严格校验默认关闭。首次连接某台服务器后，如果想开启严格

校验，去 Preferences ▸ Connection ▸ Strictly verify SSH host keys 打勾。

开启后未知主机的连接会被拒绝，这是有意为之（防中间人）。

列与列之间有细分隔线，从表头一直画到最下面一行，所以列很多时也能一眼看清

每个值属于哪一列（颜色可在偏好设置里用 Grid line 单独调整）。

权限列的两种显示

不同服务器给出的权限信息不同，本客户端会挑服务器真正提供的那种来显示，

不会编造：

服务器返回显示样子含义
MLSD 带 unix.mode（ProFTPD、vsftpd 等）-rw-r--r--、drwxr-xr-x标准 Unix 权限位
LIST 的 ls -l 输出-rw-r--r--、lrwxrwxrwx标准 Unix 权限位
只有 MLSD 的 perm 事实（pyftpdlib、pure-ftpd、IIS 等）-rawfdMT、delfdcmpMT当前账号被允许的操作，不是权限位
什么都没给空白服务器没有提供

第二种情况按 RFC 3659 定义显示，字母含义：

e 进入 · l 列出 · r 读取 · a 追加 · w 写入 · f 改名 ·

d 删除 · c 新建 · m 建目录 · p 删除目录内文件 · M/T 设置修改时间。

首字母是类型：- 文件、d 目录、l 链接。

为什么不做成 -rw-r--r-- 的样子？因为 perm 描述的是你这份账号能做什么，

而不是文件的权限位，硬套成 Unix 格式会是假信息。把鼠标悬停在文件上，

提示框会把字母展开成单词（例如 read, append, write, rename, delete）。

想改宽度：直接拖列边框，宽度会被记住。

想让列宽按内容自适应：View ▸ Auto-fit the name column（默认关闭）。

5.4 排序与筛选

  • 点任意列标题排序；再点一次切换升/降序
  • 文件夹始终排在最前面（和 Windows 资源管理器一致）
  • 每个面板的 Filter… 框可实时按名字过滤当前目录

5.5 隐藏文件

面板上的眼睛按钮，或 Ctrl+H，或菜单 View ▸ Show hidden files。

两个面板同步生效，设置会被记住。

5.6 文件大小自动补齐

有些服务器在目录列表里不返回文件大小（部分 SFTP 服务器、老式 LIST 输出）。

这种情况下：

  1. 该行 Size 列先显示 …
  2. 状态栏显示 N size(s) pending
  3. 客户端自动在后台逐个查询（FTP 用 SIZE/MDTM，SFTP 用 stat），

每 20 个刷新一次界面，不影响你继续操作

  1. 补齐后显示真实大小；服务器确实没有则显示 0 B

也可以手动触发：View ▸ Fetch missing file sizes。

如果补齐后仍然显示 …，说明该服务器拒绝 SIZE/stat，日志里会记录

N file size(s) unavailable。

  • 上传目录：递归创建远程目录结构并上传其中所有文件

6.5 并发数

Preferences ▸ Transfers ▸ Simultaneous transfers 可设 1–4。

  • SFTP：真正并行，多个文件同时传，速度更快
  • FTP/FTPS：同一条控制连接无法并行传多个文件，实际会被自动串行化，

不会出错，但也不会更快。传 FTP 时设 1 即可

失败的项目会自动排队重试，状态列显示 retrying (n)。

6.7 传输完成提示与自动刷新

每个传输（或一批传输）结束时会弹窗告知结果，并自动刷新对应面板，

新文件立刻出现在列表里。

弹窗规则

情况弹窗内容
单个下载成功标题「下载完成」，显示文件名，展开详情可看目标目录
单个上传成功标题「上传完成」，同上
单个失败标题「下载/上传完成，但有失败项」，显示服务器的原始报错，详情里有源路径与目标路径
一批全部成功标题「传输完成」，显示 N ok / 0 failed

不会每个文件弹一次。弹窗是模态的，关掉后才会弹出下一批的结果。

  • 上传完成 → 若远程面板正显示该目录，远程面板刷新

6.8 传输报错但文件其实已下载完整？

1.0.0 已修复。旧版偶发「226 Transfer complete.」被当成失败，原因是：

  • ftplib.voidresp() 只接受 2xx，且抛出异常时直接把响应原文当错误消息。

部分服务器（或中间的代理）在传输结束后会多发一行 226，于是传输明明成功，

却被报成失败，消息就是 226 Transfer complete.

  • 多出来的那行还会污染控制通道：后面每条命令都读到上一条的响应，

于是出现 550 SIZE not allowed in ASCII mode 之类的假错误，

而且会连续影响后续文件（这就是为什么总是固定某几个文件失败）。

现在的处理：

措施效果
传输结束后排空控制通道里多余的 2xx成功的传输不再被误报为失败
发命令前清掉遗留的 2xx后一个文件不受前一个的影响（FTP 每条命令只有一个响应，所以发命令前还等着的响应一定是多余的）
SIZE 查询先切二进制模式，失败不影响传输不再出现 550 SIZE not allowed in ASCII mode
首次建立数据连接被拒时排空并重试一次偶发错位可自动恢复
下载前先检查取消状态取消的传输不会向服务器发出半截命令

如果你仍看到下载报错，请把日志标签页里的完整内容发我——里面能看出是服务器拒绝、

权限不足、磁盘满，还是路径问题。

每个传输（或一批传输）结束时会弹窗告知结果，并自动刷新对应面板，

新文件立刻出现在列表里。

弹窗规则

8.1 自动保存

8.2 文件格式

纯 INI 文本，可以直接用记事本编辑、备份、迁移到其他机器：

name = Production web server
protocol = ftp
host = ftp.example.com
port = 21

password = s3cr3t

port = 22

password = pw

字段说明：

字段说明

protocolftp / ftps / sftp

key_filenameSFTP 私钥路径
passive1/0，FTP 被动模式

[connections] 只是给人看的索引（名称 → 区段名），程序不依赖它，删掉也能用。

8.3 保存行为细节

情况行为
连接成功自动写入/更新 config.ini，日志提示保存的连接名
同一主机 + 用户再次连接更新原记录，不会产生重复项
连接栏密码留空重连保留 config.ini 里已存的密码，不会清空
关闭程序把该连接最后所在的本地/远程目录写回记录
连接名重复自动加后缀，如 web (2)
旧版本 settings.json 里的站点首次启动自动迁移进 config.ini（仅当 config.ini 为空）

安全提示：密码在 config.ini 里是明文保存的。INI 格式没有可用的密钥

管理，这样做是为了让文件可以直接迁移、被其他工具读取。请自行保证该文件的

访问权限。不想落盘就让连接栏的密码框留空后再连接。

8.4 连接名规则

  • 建议名格式：用户名@主机；非标准端口写成 用户名@主机:端口（如 u@h:2121）
  • 连接对话框里留空无法确定；连接栏留空则自动使用建议名
  • 从站点管理或最近连接再次连接时，原名字会保留，不会被自动名覆盖

13. 常见问题排查

连不上服务器

现象可能原因与处理
Connection refused - is the server running, and is the port right?端口不对，或服务器没启动，或防火墙拦截
Host not found - check the server name主机名拼错，或 DNS 解析失败
Connection timed out网络不通，或被防火墙丢包（可在偏好里加大超时）
Authentication failed - check the user name and password用户名或密码错误（SFTP 时也可能是私钥不对）
Server refused the command (530 …)服务器拒绝登录，常见于未授权 IP 或账号被锁

中文文件名显示乱码

FTP 服务器编码不一致导致。到 Preferences ▸ Connection ▸ FTP encoding

尝试改为 gbk 或 latin-1。SFTP 一律使用 UTF-8，正常不会乱码。

远程文件大小显示 … 或 0 B

该服务器未在目录列表里返回大小，且拒绝 SIZE/stat 查询。日志里会有

N file size(s) unavailable。这不影响传输，只是无法预显示大小。

权限修改失败

SITE CHMOD 不是标准 FTP 命令，很多服务器（尤其 Windows FTP）不支持。

SFTP 的 chmod 一般都能用。

传输中途卡住或取消后无法继续

对 FTP 取消传输会关闭控制连接（协议决定），下次操作会自动重连。日志里会记录。

SFTP 取消只关闭当前文件句柄，连接保持。

端口 21 上用 SFTP

如果服务器确实是 SSH 监听在 21 端口，选 SFTP + 端口 21 即可；

否则请确认服务端配置，或改用标准的 22 端口。

界面字体缺失提示

控制台可能打印 QFontDatabase: Cannot find font directory …。

这是 PyQt5-Qt5 的 Windows 包不带字体目录导致的提示，程序使用系统字体，

不影响任何功能。

14. 已知限制

  1. SFTP 未在真实 SSH 服务器上做过端到端验证。本机没有可用的 sshd，

代码路径完整（密码登录、私钥登录、keepalive、主机密钥校验），接口与 FTP

完全一致，但请在自己的服务器上确认一次。

  1. FTP 并发实际被串行化。同一条 FTP 控制连接不能并行传多个文件，

客户端用会话锁保证不会出错，但并发数对 FTP 不会提速。

  1. 密码明文存储在 config.ini 中，见 8.3 节的安全提示。
  2. 编辑器一次性载入整个文件，超过 4 MB 会先提示确认，不适合编辑超大文件。
  3. Owner 列默认隐藏（省约 92 px）；Permissions 列默认显示。

两列都可以在 View 菜单里随时开关。

  1. 权限列的显示形式取决于服务器：给出 unix.mode 时显示

-rw-r--r-- 这样的权限位；只给 MLSD perm 时显示该账号被允许的

操作字母（如 -rawfdMT）——详见 5.3 节。两者含义不同，客户端不会

把后者硬套成 Unix 格式。

  1. 严格的 SSH 主机密钥校验默认关闭，首次连接前请确认服务器身份。
