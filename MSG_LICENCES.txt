Record the licence of every dependency

requirements.txt listed what to install but not under what terms, which is the
first thing anyone needs before redistributing the exe.

* every pin now carries a "licence:" line, and the file ends with a LICENCES
  section that groups all 25 by their terms
* the identifiers are SPDX, read from each distribution's own metadata
  (License-Expression, then License, then the OSI classifier, then a licence
  file inside the wheel) rather than typed from memory
* 7 gaps had to be resolved from the packages themselves: cryptography is
  "Apache-2.0 OR BSD-3-Clause", typing_extensions "PSF-2.0", packaging
  "Apache-2.0 OR BSD-2-Clause", and pyinstaller's is
  "GPL-2.0-or-later WITH Bootloader-exception" - that exception is precisely
  what allows a GPL build tool to package a program under other terms, so it
  was worth stating exactly

The audit will not let them drift
- tools/deps_report.py now compares the table with the installed metadata and
  prints any disagreement; the run reports "all 25 entries agree with the
  installed metadata"
- comparing free-text licences needed real normalisation: an earlier attempt
  stripped the text so aggressively that "GPLv2" came out as "2gplv2" and
  "GNU AFFERO GPL 3.0" as "gpl30".  It now recognises a family and the version
  written beside it, which makes "GPL v3" and "GPL-3.0-only" equal without
  making them equal to version 2
- the generated file stays ASCII-only and still parses: pip's own
  parse_requirements() reads all 25 out of it

Two things worth flagging, now written down
- PyQt5 and PyQtWebEngine are GPL-3.0 or commercial from Riverbank.
  Distributing the exe under the GPL satisfies that; a closed source build
  needs the commercial licence.  The bundled Qt DLLs are used under the LGPL
  option, which dynamic linking satisfies
- PyMuPDF is AGPL-3.0, but only tools/build_manual.py uses it, to add the
  manual's table of contents links and bookmarks.  It is a build tool and is
  not part of the distributed exe

README's dependency section was stale - it said 22 pins and 9 build packages,
where there are 25 and 12 - and now carries the licence table and the PyQt5
warning.

Verified: 69 session-layer and 320 UI checks pass; requirements.txt is
ASCII-only, all 25 pins have a licence line, and pip parses it.
